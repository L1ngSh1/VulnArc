# VulnArc 终端工作台 · 设计草案

状态：**提议，未实现**。日期：2026-10-07。

This is a design proposal, not an available interface. The first iteration proposes a
read-only, keyboard-driven terminal workbench over existing VA records. No framework,
new command or release date is committed by this document.

## 1. 先解决什么

现在用户可以用命令登记、阅读、核对报告。工作台只解决日常浏览时反复输入命令的问题：
**打开工作区 → 选案例 → 读主报告/翻译 → 查材料**。

本草案把“CLI 审美工作台”暂定为真正运行在终端里的 TUI，而不是仿终端的网页。
网页方案属于另一个交付面，待方向确认再考虑。CLI 保留完整独立用途，管道输出不改变。

## 2. 视觉语言：安静的档案室，而不是炫技控制台

- **排版：** 等宽字体、细边框、明确对齐。大标题只出现一次，把空间留给案例和正文。
- **配色：** 终端原生背景；青色标识焦点，绿色表示本次已核对，黄色表示未核对/待处理，红色表示错误。
- **语义：** 颜色始终配文字；“哈希一致”不是“漏洞已验证”，“登记状态”不是“平台处理状态”。
- **克制：** 不加启动动画、扫描雷达、伪实时数据或没有真实来源的统计大屏。
- **无色可读：** 不依靠颜色区分选择与状态；中文宽度、长路径、浅色终端都要可用。

## 3. 信息布局

下方全部为虚构数据的线框图，不是当前 CLI 截图；尺寸与按键均为候选设计。

```text
┌─ VULNARC / WORKBENCH ────────────────────────────────────────────────────┐
│ Workspace: /path/to/private/archive      Mode: READ-ONLY                 │
├────────────────────┬─────────────────────────────────────────────────────┤
│ CASES              │ VA-2026-0001 · Example report                       │
│ > VA-2026-0001     │ [Overview] [Primary] [Translation]                  │
│ VA-2026-0002       │ [Materials]                                         │
│                    ├─────────────────────────────────────────────────────┤
│                    │ Selected material: primary_report                   │
│                    │ Integrity: NOT CHECKED                              │
│                    │                                                     │
│                    │ Report content / material details                   │
│                    │                                                     │
├────────────────────┴─────────────────────────────────────────────────────┤
│ Tab Focus · ↑↓ Select/Scroll · Enter Open · Esc Back · q Quit            │
└──────────────────────────────────────────────────────────────────────────┘
```

首版只需要三个区域：工作区栏、案例列表、详情阅读区。底部给当前上下文可用按键。
登记回执里的编号与核对提示延续现有风格，不把成功提示改成未经验证的庆祝状态。

### 四个详情视图

| 视图 | 内容 | 核对约定 |
| --- | --- | --- |
| 概览 | 编号、项目、标题、评分归属、登记依据、处理状态 | 元数据展示，不隐含材料已核对 |
| 主报告 | 原件出处与全文 | 展示同一次已核对的字节，保留不支持的 Markdown 内容 |
| 已登记翻译 | 同主报告；无翻译时显示空状态 | 不生成翻译，多份材料必须明确选择 |
| 材料 | 角色、路径与逐项状态 | 用户显式触发核对；单项出错不吞掉其余条目 |

## 4. 交互与状态

- 用户显式指定工作区。切换工作区后清空旧选择和旧校验状态，避免把不同档案混在一起。
- `Tab` 切焦点；列表用上下键选案例、`Enter` 打开；正文区上下键滚动，`Esc` 返回。
- 视图切换控件只展示可用操作。多份同角色材料显示候选，不默选第一份。
- 空库、无翻译、原件缺失、哈希变化、无权限和损坏元数据均有明确文本状态。
- 首次进入不显示绿色“全库正常”。核对结果标明本次读取，不声称磁盘以后不会变化。
- 刷新时重新读取，不继续展示过期的成功状态；失败时不把上一份正文冒充当前材料。
- 窄窗口切为“列表 → 详情”的单列导航；过窄时说明需要扩大窗口，不截掉关键错误。
- 退出恢复终端状态。普通 CLI 与重定向场景继续使用现有命令，不强制进入 TUI。

## 5. 工程边界

- 第一版只读已有 VA 案例。登记、更新、笔记编辑、搜索、统一统计与 RPT/HYP 混合看板另行规划。
- 复用现有模型、案例选择和材料核对逻辑，不另写一套 ID 分配、哈希或存储规则。
- UI 通过明确的数据/错误结果调用逻辑层，不解析 CLI 的彩色输出，不拼 shell 执行阅读命令。
- 如需要调整逻辑接口，另列小步改动，保持原 CLI 的 stdout/stderr、退出码和字节输出契约。
- 不新增数据库、索引或持久缓存；查看操作不改快照、笔记、mtime，不产生锁和历史事件。
- 无自动联网、附件执行或 HTML 执行。截图与演示只使用合成案例。
- 框架选择在独立原型阶段比较，先验证中文、滚动、窗口缩放和无色操作，再决定依赖。

## 6. 分步推进与验收

| 步骤 | 交付 | 通过标准 |
| --- | --- | --- |
| A · 设计确认 | 布局、视图、状态与键盘路径 | 明确是终端 TUI；工作区和校验状态没有歧义 |
| B · 合成原型 | 只使用虚构案例的交互原型 | 80/120/160 列可读；键盘可完成选案例、读翻译、查材料、退出 |
| C · 接入已有逻辑 | 只读 VA 浏览 | 同一 ID 得到与 CLI 一致的材料选择与哈希判断；失败不展示错正文 |
| D · 回归与交付 | 测试、合成演示、安装说明 | 全文尾部可达，HTML 内容保留，档案哈希/mtime 不变，旧 CLI 测试通过 |

回退时移除或禁用新增入口即可回到原 CLI，不安排数据迁移。
新入口、可选依赖与实际回退方式需要在实施计划中定稿；本草案不等于开始实现。
